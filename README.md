# 数据帧回放工具

把按行分割的十六进制数据文件按帧解析出来，经 UDP 单播或组播发出去。

行首常见的事件标识、序号、汉字标识可以剥掉；发送前还能按条件筛选行、
按规则改字节（插入、替换、删除，以及序号、时间戳、长度、校验和这些计算值）。
界面同时显示数据原文、实际发出的字节和运行日志。

跨 Windows / Linux / macOS。

## 快速上手

1. **打开文件** —— 选一个数据文件。1GB 以内都能开，索引在秒级建好。
2. **配解析规则** —— 选编码，再决定怎么剥掉行首的干扰内容。
   原文视图会立刻把「被丢弃的前缀」压暗、「被采用的数据」提亮，配对了一眼就能看出来。
3. **配发送目标** —— 单播填 IP 和端口；组播还要选出站网卡。本地绑定地址会读取
   本机 IPv4 网卡供选择，选“自动”时绑定 `0.0.0.0`。
4. **配节奏** —— 发送间隔、起止行、是否循环。
5. **开始发送**。

配置面板顶部会实时列出配置里的问题，有阻止性错误时「开始发送」是灰的。

## 各部分说明

### 解析规则

数据行长这样：

```
[TX] 000123 发送 01 A5 3F 2B
└────── 前缀 ──────┘└─ 数据 ─┘
```

两种剥法二选一：

- **按字段丢弃**：指定分隔符，丢掉行首 N 个字段
- **按字符跳过**：跳过行首 N 个字符。按字符计，一个汉字算一个

**编码**很重要。带汉字的数据文件在 Windows 上常是 GBK，按 UTF-8 解会乱码。
选错了原文视图里的汉字会变成方块，换一个就行。

数据里的空白和 `:` `-` `,` 会被忽略。遇到其他非十六进制字符时数据就到此为止，
其后按尾注处理（灰色斜体显示）—— 所以行尾写注释不影响使用。

### 筛选规则

两类条件，可以叠加多条，**全部满足**才发送；每条都能单独取反或停用。

- **行字段**：某个字段等于 / 包含某个文本
- **数据字节**：某个偏移上的字节等于某个值，可以带掩码只比较部分位

字节偏移填负数表示从帧尾倒数：`-2` 配两字节就是匹配最后两字节。

被筛掉的行在原文视图里整体压暗，能直接看出筛选选中了哪些。

### 修改规则

分两个阶段执行，这是这部分的关键：

```
原始帧 ──阶段一──▶ 中间帧 ──阶段二──▶ 待发帧
     插入/替换/删除      长度/序号/时间戳/校验和
```

- **阶段一**的偏移一律按**原始数据**数。在 offset 5 插两个字节，
  不会让另一条「offset 10 替换」跑偏 —— 规则之间互不影响。
- **阶段二**在结构改完之后执行，按你排的先后顺序来。
  **校验和要排在最后**，因为长度字段通常也在校验范围内。排错了界面会提醒。

这么分的原因很实在：插入或删除字节之后，原报文的长度字段和校验和就全废了。
先改结构再算派生值，改完的帧才依然是合法报文。

校验和支持累加和、异或、CRC16（CCITT / MODBUS / XMODEM）、CRC32。
如果校验和字段落在自己的计算范围内，会先清零再算 —— 这是多数协议的约定。

### 节奏控制

间隔可以填微秒、毫秒或秒。两种模式：

- **普通节拍**：睡眠驱动，几乎不占 CPU，误差取决于系统调度粒度（通常 1ms 级）
- **高精度**：自旋等待，误差能压到个位数微秒，代价是占满一个 CPU 核心

两种都是**软实时**。操作系统调度仍会造成偶发抖动，这没法根除，
所以状态栏左侧有一条时序带，把真实的帧间隔画成刻度：
齐整的梳齿就是稳，冒出来的就是那一帧被系统耽误了。旁边还有 p50 / p99 数值。

### 配置档

解析、筛选、修改、目标、节奏五部分能一起存成 JSON 文件，换台机器直接载入。

## 状态栏上要留意的几个数

- **缓冲满丢弃** —— 内核发送缓冲满导致的丢帧。**UDP 不会告诉任何人这件事**，
  所以单独列出来。数字不为零说明发得比机器能承受的快，
  可以调大发送缓冲或放宽间隔。
- **跳过** —— 解析失败的行。日志里按错误类型聚合，能看到是哪一类、有多少行。
- **已筛掉** —— 被筛选规则排除的行，跟解析错误是两回事。
- **修改未生效** —— 偏移越界或区间冲突导致某条修改规则被跳过，帧本身照常发出。

## 已知取舍

- 高频发送时「发送数据」视图只能采样显示，标题上会写明实际已发多少帧。
  要逐帧核对就用**单步**：暂停后点一次发一帧。
- 1GB 文件配微秒间隔在同一次任务里不会同时出现（那是几百 GB/s 的数据率）。
  引擎两者都支持，但没为这个组合做额外优化。
- 10μs 间隔约合 10 万包/秒，这个量级的瓶颈通常在网卡和内核协议栈，不在定时器。
- 组播目前只支持 IPv4。
