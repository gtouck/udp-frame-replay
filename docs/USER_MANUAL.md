# 数据帧回放工具用户手册：规则配置

本文详细说明解析规则、筛选规则和修改规则。发送目标、发送间隔等基础操作见项目
[README](../README.md)。

## 1. 规则执行顺序

每一行数据依次经过以下处理：

```text
文件中的一行
  │
  ├─ 1. 解析规则：文本解码、去掉前缀、十六进制解码
  │       解析失败 → 跳过该行
  │
  ├─ 2. 筛选规则：检查原始行字段和解析出的原始字节
  │       不满足 → 计入“已筛掉”，不发送
  │
  ├─ 3. 修改规则阶段一：插入、替换、删除
  │
  ├─ 4. 修改规则阶段二：序号、时间戳、长度、校验和
  │
  └─ 5. UDP 发送
```

因此：

- 筛选规则看到的是修改前的数据。
- 插入、替换、删除的偏移基于原始帧。
- 序号、时间戳、长度、校验和的偏移基于阶段一完成后的帧。
- “原文”视图用于检查解析和筛选结果；“发送数据”视图显示真正发出的修改后字节。

## 2. 通用约定

### 2.1 序号与偏移

- 文件行号从 `1` 开始。
- 行字段序号和字节偏移从 `0` 开始。
- 字节偏移为非负数时，从帧头开始计算；`0` 是第一个字节。
- 字节偏移为负数时，从帧尾倒数；`-1` 是最后一个字节，`-2` 是倒数第二个字节。

例如，帧为 `10 20 30 40 50`：

| 偏移 | 指向的字节 |
| ---: | :--- |
| `0` | `10` |
| `2` | `30` |
| `-1` | `50` |
| `-2` | `40` |

### 2.2 字节范围

长度和校验和使用左闭右开区间 `[start, end)`：包含 `start`，不包含 `end`。

- `start` 和 `end` 都可以为负数，含义与负偏移相同。
- `end = 0` 是特殊写法，表示一直到帧尾，不表示在帧头结束。

对于 8 字节帧：

| 配置 | 实际范围 | 字节数 |
| :--- | :--- | ---: |
| `{ "start": 0, "end": 0 }` | `[0, 8)`，整帧 | 8 |
| `{ "start": 2, "end": 6 }` | `[2, 6)` | 4 |
| `{ "start": 2, "end": -2 }` | `[2, 6)` | 4 |
| `{ "start": -4, "end": 0 }` | `[4, 8)` | 4 |

### 2.3 十六进制写法

筛选条件和修改值中的十六进制文本不区分大小写，并允许使用空白、冒号、短横线或逗号分隔：

```text
01 A5 3F 2B
01:A5:3F:2B
01-A5-3F-2B
01A53F2B
```

以上四种写法都表示 `01 A5 3F 2B`。十六进制数字必须成对；`01 A5 3` 是错误配置。
这里列出的分隔符固定用于筛选条件和修改值，不受解析规则中“忽略字符”的自定义值影响。

## 3. 解析规则

解析规则把一行文本拆成“前缀、数据、尾注”，并把数据部分转换成字节。

### 3.1 编码

| 界面选项 | 适用情况 |
| :--- | :--- |
| `UTF-8` | UTF-8 文件和纯 ASCII 文件，默认选项 |
| `GBK（简体中文）` | Windows 工具产生的含中文 GBK 文件 |
| `Latin-1` | 纯 ASCII 或未知单字节编码的兜底选项 |

编码选错时，中文可能显示成替换字符。工具不会仅因乱码自动判定解析失败，因此应先在“原文”视图确认文本是否正常。

### 3.2 按字段丢弃

“按字段丢弃”先按指定分隔符切分整行，再丢弃开头若干字段，下一字段即为数据起点。

可选分隔符：

- 空白：空格或 Tab。
- 逗号。
- Tab。
- 自定义：配置字符串中的任意一个字符都是分隔符。例如 `|;` 表示竖线或分号都可分隔字段。

“连续分隔符算一个”的行为：

- 开启：`A,,B` 按两个字段 `A`、`B` 处理。
- 关闭：`A,,B` 按三个字段 `A`、空字段、`B` 处理。

使用空白分隔符时通常应开启此选项，以免对齐用的多个空格产生空字段。

#### 示例：按字段解析

数据：

```text
[RX] 000123 发送 01:A5-3F,2B  # 温度报文
```

配置（对应配置档中的 `config.parse`）：

```json
{
  "encoding": "utf8",
  "prefix": {
    "mode": "fields",
    "delimiter": { "kind": "whitespace" },
    "collapse": true,
    "skipFields": 3
  },
  "hex": { "ignoreChars": ":-," }
}
```

输出结果：

```text
前缀：[RX] 000123 发送 
数据：01:A5-3F,2B
尾注：  # 温度报文
字节：01 A5 3F 2B
```

`skipFields = 3` 表示丢弃 `[RX]`、`000123`、`发送` 三个字段。分隔符后的数据从第 4 个字段开始。

### 3.3 按字符跳过

“按字符跳过”直接跳过行首指定数量的 Unicode 字符。一个汉字算一个字符，不按 UTF-8 字节数计算。

#### 示例：按字符解析

数据：

```text
[RX] 000123 发送 01 A5 3F 2B
```

`[RX] 000123 发送 ` 共 15 个字符，配置如下：

```json
{
  "encoding": "utf8",
  "prefix": {
    "mode": "chars",
    "skipChars": 15
  },
  "hex": { "ignoreChars": ":-," }
}
```

输出结果：

```text
前缀：[RX] 000123 发送 
数据：01 A5 3F 2B
字节：01 A5 3F 2B
```

字符模式适合固定宽度前缀。如果序号位数或前缀长度会变化，应优先使用字段模式。

### 3.4 忽略字符与尾注

“忽略字符”只作用于数据部分。空白始终会被忽略；默认还忽略 `:`、`-`、`,`。

解析器会连续收集十六进制数字，并按每两位组成一个字节。遇到既不是十六进制数字、也不是忽略字符的内容时立即停止，剩余内容作为尾注。例如 `#` 不在默认忽略字符中，所以可作为注释起点。

注意：分隔符只会被跳过，不会强制字节边界。因此 `0 1 A 5` 仍会得到 `01 A5`。建议始终把每个字节写成两位。

### 3.5 解析错误

| 错误 | 触发条件 | 处理结果 |
| :--- | :--- | :--- |
| 没有十六进制数据 | 去掉前缀后未读到十六进制数字 | 跳过该行 |
| 十六进制字符数为奇数 | 例如 `01 A5 3` | 跳过该行；预览仍可显示已组成的完整字节 |
| 字段数不足 | 丢弃的字段数超过该行实际字段数 | 跳过该行 |
| 行长度不足 | 字符模式要求跳过的字符数超过行长 | 跳过该行 |

解析失败计入状态栏“跳过”，不会计入“已筛掉”。日志会按错误类型聚合，并列出样例行号。

## 4. 筛选规则

筛选规则在解析成功后执行，用于决定一帧是否发送。没有启用的筛选规则时，所有解析成功的行都会进入修改阶段。

### 4.1 多规则关系、停用与取反

- 所有启用的规则之间是“与”关系：必须全部满足才发送。
- 关闭规则左侧的勾选框后，该规则完全不参与判断。
- 点击“取反”后，该条规则由“必须匹配”变成“必须不匹配”。

假设有规则 A、B：

| A | B | 是否发送 |
| :---: | :---: | :---: |
| 满足 | 满足 | 是 |
| 满足 | 不满足 | 否 |
| 不满足 | 满足 | 否 |
| 不满足 | 不满足 | 否 |

若 B 开启“取反”，则只有“A 满足且 B 不满足”时发送。

### 4.2 行字段条件

行字段条件检查原始文本行中的某个字段：

- 字段序号从 `0` 开始，并且始终从原始行首计算，不是从数据体开始计算。
- `等于`：字段内容必须完全相同。
- `包含`：字段中出现指定文本即可。
- 比较区分大小写，不会自动去除字段内部字符。
- 字段不存在时视为不匹配。

字段的切分方式沿用解析规则中的分隔符和“连续分隔符算一个”设置。如果解析规则使用字符模式，字段条件改用“空白分隔、连续空白算一个”。

对于以下数据：

```text
[RX] 000101 温度 A1 05 10 FE
```

字段依次为：

| 字段序号 | 内容 |
| ---: | :--- |
| `0` | `[RX]` |
| `1` | `000101` |
| `2` | `温度` |
| `3` | `A1` |

解析规则即使丢弃前 3 个字段，筛选中的字段 `0` 仍然是 `[RX]`。

### 4.3 数据字节条件

数据字节条件检查解析后的原始字节：

- “偏移”是期望值第一个字节的位置。
- “字节”可以包含一个或多个字节。
- 负偏移从帧尾倒数。例如偏移 `-2`、值 `12 34` 表示最后两个字节必须是 `12 34`。
- 帧长度不足以容纳要比较的全部字节时，视为不匹配。

掩码用于只比较部分位。计算方式是：

```text
(实际字节 & 掩码) == (期望字节 & 掩码)
```

例如期望值 `A0`、掩码 `F0` 会匹配 `A0` 到 `AF`；掩码必须与期望值字节数相同。

### 4.4 筛选示例

数据：

```text
[RX] 000101 温度 A1 05 10 FE
[RX] 000102 温度 A2 05 1F FE
[TX] 000103 温度 A1 05 20 FE
[RX] 000104 告警 A1 06 10 FD
```

解析配置为“空白分隔、连续空白算一个、丢弃 3 个字段”。筛选配置（对应 `config.filter`）：

```json
{
  "rules": [
    {
      "condition": {
        "kind": "field",
        "index": 0,
        "op": "equals",
        "value": "[RX]"
      },
      "negate": false,
      "enabled": true
    },
    {
      "condition": {
        "kind": "bytes",
        "offset": 0,
        "value": "A0",
        "mask": "F0"
      },
      "negate": false,
      "enabled": true
    },
    {
      "condition": {
        "kind": "bytes",
        "offset": 1,
        "value": "05",
        "mask": null
      },
      "negate": false,
      "enabled": true
    }
  ]
}
```

输出结果：

| 行 | 解析出的字节 | 判断 | 结果 |
| ---: | :--- | :--- | :--- |
| 1 | `A1 05 10 FE` | `[RX]`；`A1 & F0 = A0`；偏移 1 为 `05` | 发送 |
| 2 | `A2 05 1F FE` | `[RX]`；`A2 & F0 = A0`；偏移 1 为 `05` | 发送 |
| 3 | `A1 05 20 FE` | 字段 0 是 `[TX]` | 筛掉 |
| 4 | `A1 06 10 FD` | 偏移 1 是 `06` | 筛掉 |

若要排除最后一个字节为 `FE` 的帧，可再添加“数据字节：偏移 `-1`、字节 `FE`”，并对该规则开启“取反”。

### 4.5 无效配置

以下问题会在配置面板顶部显示为阻止性错误，修正前不能开始发送：

- 字节值为空。
- 字节值或掩码不是合法的偶数位十六进制文本。
- 掩码字节数与期望值不同。

被停用的规则不参与预检，也不参与发送时判断。

## 5. 修改规则

修改规则在筛选之后执行。没有启用的修改规则时，解析出的字节原样发送。

### 5.1 两阶段模型

```text
原始帧 ── 阶段一 ──▶ 中间帧 ── 阶段二 ──▶ 待发帧
          插入                 序号
          替换                 时间戳
          删除                 长度
                               校验和
```

无论规则卡片怎样交错排列，所有阶段一规则都会先完成，然后才执行阶段二规则。

- 阶段一的所有偏移都基于原始帧，各规则不会因前面的插入或删除而发生偏移漂移。
- 阶段二的偏移和范围都基于阶段一完成后的中间帧，并按规则卡片中的相对顺序依次执行。
- 阶段二规则若写入同一位置，后执行的规则会覆盖前一条规则的结果。
- 通常应把校验和放在最后，否则后续规则会改动已经参与校验的数据。界面会对此给出警告。

### 5.2 阶段一：插入、替换、删除

#### 插入

在指定偏移指向的原始字节之前插入数据，不覆盖原字节。

```text
原始：00 11 22 33
配置：偏移 2，字节 AA BB
结果：00 11 AA BB 22 33
```

偏移 `0` 表示加到帧头；正偏移等于原始帧长度时表示追加到帧尾。偏移 `-1` 表示插在最后一个原始字节之前。

#### 替换

从指定偏移开始，用配置值覆盖相同数量的原始字节。

```text
原始：00 11 22 33
配置：偏移 1，字节 AA BB
结果：00 AA BB 33
```

替换不会改变帧长度。剩余字节不足时，该规则对该帧不生效。

#### 删除

从指定偏移开始删除指定数量的原始字节。

```text
原始：00 11 22 33 44
配置：偏移 2，长度 2
结果：00 11 44
```

删除长度必须至少为 1。剩余字节不足时，该规则对该帧不生效。

#### 多条结构规则

假设原始帧为 `00 11 22 33 44 55`，同时配置：

```text
插入：偏移 0，字节 AA AA
替换：偏移 3，字节 EE
```

输出是：

```text
AA AA 00 11 22 EE 44 55
```

替换仍然作用于原始偏移 3 的 `33`，不会因前面插入两个字节而改到原始偏移 1。

同一偏移的多条插入按规则卡片顺序写入。替换和删除不能覆盖同一段原始字节；能提前确定的冲突会阻止启动，只有运行时才能发现的冲突会跳过后发生冲突的规则，并计入“修改未生效”。

### 5.3 阶段二：序号

序号规则把递增计数值写入指定位置。

| 字段 | 说明 |
| :--- | :--- |
| 偏移 | 中间帧中的写入位置 |
| 宽度 | 1、2、4 或 8 字节 |
| 字节序 | 大端或小端 |
| 起始 | 第一帧写入的值 |
| 步长 | 每次成功写入后的增加量 |
| 循环时归零 | 文件进入下一轮时恢复为起始值 |

示例：偏移 `0`、宽度 2 字节、大端、起始 `100`、步长 `5`：

```text
第 1 帧：00 64 ...
第 2 帧：00 69 ...
第 3 帧：00 6E ...
```

序号按修改规则实际生效的帧递增。筛掉的行不会消耗序号。

### 5.4 阶段二：时间戳

时间戳规则在处理每帧时读取当前时间并写入指定位置。

| 字段 | 选项 |
| :--- | :--- |
| 单位 | 毫秒、微秒 |
| 基准 | Unix 纪元、本次发送起 |
| 宽度 | 1、2、4 或 8 字节 |
| 字节序 | 大端、小端 |

示例：若本次发送开始后恰好经过 1234 毫秒，配置“本次发送起、毫秒、4 字节、大端、偏移 0”，写入结果为：

```text
00 00 04 D2
```

实际输出随处理时刻变化。Unix 微秒时间戳通常应使用 8 字节；若数值超过所选宽度，只写入低位字节。

### 5.5 阶段二：长度

长度规则计算配置范围的字节数，并把数值写入指定位置。

```text
中间帧长度：8 字节
配置范围：start = 2，end = -2
范围换算：[2, 6)
写入值：4
```

“含长度字段自身”会在范围长度上额外加上长度字段的宽度。例如范围长 6 字节、长度字段宽 2 字节，勾选后写入 8。若配置范围本身已经包含长度字段，不要再勾选，否则会重复计数。

示例：8 字节帧，偏移 `0`、宽度 2 字节、范围 `[2, 8)`、不含自身：

```text
大端结果：00 06 ...
小端结果：06 00 ...
```

### 5.6 阶段二：校验和

| 界面算法 | 说明 | 写入宽度 |
| :--- | :--- | ---: |
| 累加和 8 | 所有字节相加，结果按 8 位回绕 | 1 字节 |
| 累加和 16 | 所有字节相加，结果按 16 位回绕 | 2 字节 |
| 异或 8 | 所有字节逐字节异或 | 1 字节 |
| CRC16-CCITT | CRC-16/IBM-3740，常称 CCITT-FALSE | 2 字节 |
| CRC16-MODBUS | 标准 CRC-16/MODBUS | 2 字节 |
| CRC16-XMODEM | 标准 CRC-16/XMODEM | 2 字节 |
| CRC32 | CRC-32/ISO-HDLC | 4 字节 |

校验和宽度由算法决定。字节序只影响多字节结果如何写入帧。

如果校验和字段落在自己的计算范围内，工具会先把该字段清零，再计算校验和。例如 6 字节帧的最后 2 字节是 CRC 占位，可使用：

```json
{
  "kind": "checksum",
  "offset": -2,
  "algorithm": "crc16Ccitt",
  "endian": "big",
  "range": { "start": 0, "end": -2 }
}
```

这里计算 `[0, len - 2)`，结果写入最后两个字节。

### 5.7 字节序与数值溢出

数值 `0x1234` 以 2 字节写入时：

```text
大端：12 34
小端：34 12
```

序号、时间戳和长度若超过配置宽度可表示的最大值，只保留低位。例如 `0x012A` 写入 1 字节时得到 `2A`。工具不会为此自动扩大字段。

### 5.8 修改规则组合示例

数据（解析后的原始字节相同）：

```text
[TX] 000001 数据 AA BB CC DD 00 00
[TX] 000002 数据 AA BB CC DD 00 00
```

修改配置（对应 `config.mutate`）：

```json
{
  "rules": [
    {
      "op": { "kind": "insert", "offset": 0, "value": "5A A5" },
      "condition": null,
      "enabled": true
    },
    {
      "op": { "kind": "replace", "offset": 2, "value": "10" },
      "condition": null,
      "enabled": true
    },
    {
      "op": { "kind": "delete", "offset": 3, "length": 1 },
      "condition": null,
      "enabled": true
    },
    {
      "op": {
        "kind": "sequence",
        "offset": 2,
        "width": "w1",
        "endian": "big",
        "start": 1,
        "step": 1,
        "resetEachLoop": false
      },
      "condition": null,
      "enabled": true
    },
    {
      "op": {
        "kind": "length",
        "offset": 3,
        "width": "w1",
        "endian": "big",
        "range": { "start": 4, "end": -2 },
        "includeSelf": false
      },
      "condition": null,
      "enabled": true
    },
    {
      "op": {
        "kind": "checksum",
        "offset": -2,
        "algorithm": "sum16",
        "endian": "big",
        "range": { "start": 0, "end": -2 }
      },
      "condition": null,
      "enabled": true
    }
  ]
}
```

输出推导：

```text
原始帧：                  AA BB CC DD 00 00
阶段一插入/替换/删除后：  5A A5 AA BB 10 00 00
```

阶段二依次写序号、长度、累加和。范围 `[4, -2)` 只包含 `10`，所以长度是 1。

```text
第 1 帧：5A A5 01 01 10 01 11
第 2 帧：5A A5 02 01 10 01 12
```

第 1 帧的累加和为 `5A + A5 + 01 + 01 + 10 = 0x0111`；第 2 帧为 `0x0112`。

### 5.9 条件修改：配置档高级用法

每条修改规则都有 `condition`。值为 `null` 时对所有通过筛选的帧生效；也可以填入与筛选规则相同的行字段或数据字节条件。

当前图形界面没有修改条件编辑控件；需要此功能时，可保存配置档后编辑 JSON，再载入配置档。例如仅替换原始第一个字节为 `A1` 的帧：

```json
{
  "op": { "kind": "replace", "offset": 1, "value": "FF" },
  "condition": {
    "kind": "bytes",
    "offset": 0,
    "value": "A1",
    "mask": null
  },
  "enabled": true
}
```

阶段一的字节条件检查原始帧；阶段二的字节条件检查阶段一结果以及前面已执行的阶段二结果。行字段条件始终检查原始文本行。

### 5.10 修改未生效

以下运行时问题不会丢弃整帧，而是跳过有问题的修改规则，继续发送其余结果：

- 偏移加上操作宽度后超出帧尾。
- 长度或校验范围越界。
- 使用负偏移或条件规则后，两条结构修改在某一帧上发生范围冲突。

这些问题会计入状态栏“修改未生效”，日志记录首个样例行及问题次数。无条件规则间固定的非负范围冲突、空修改值、删除长度为 0 等可提前确定的问题会在预检时直接阻止启动。

## 7. 推荐配置步骤

1. 打开文件，只配置编码和解析规则，确认“原文”视图中前缀、数据、尾注划分正确。
2. 添加筛选规则，确认应发送的行保持高亮，被筛掉的行整体变暗。
3. 先添加插入、替换、删除，使用“发送数据”视图核对中间结构。
4. 再添加序号、时间戳、长度，最后添加校验和。
5. 首次验证时使用较慢间隔或“暂停 → 单步”，逐帧核对实际发送字节。
6. 确认配置面板没有阻止性错误，且状态栏“修改未生效”为 0，再提高发送速率。

## 8. 常见问题

### 为什么筛选值与“发送数据”视图对不上？

筛选发生在修改之前，它比较的是解析出的原始字节；“发送数据”显示的是修改后的字节。

### 为什么插入后，另一条替换规则没有向后移动？

阶段一的所有偏移都按原始帧计算。这可以让每条结构规则直接对照原始协议布局，不需要手工累计前面规则造成的位移。

### 为什么 CRC 与接收端不一致？

依次检查算法变体、计算范围、结果字节序和校验字段是否应包含在范围中，并确认校验和规则位于所有计算值规则之后。

### 为什么长度比预期多出字段宽度？

检查“含长度字段自身”。该选项会在所选范围长度之外再加一次长度字段宽度；如果范围已经包含长度字段，应关闭它。

### 为什么某些短帧没有被修改？

规则的偏移、写入宽度或范围可能超出该帧。工具会继续发送该帧，但跳过越界规则，并增加“修改未生效”计数。
